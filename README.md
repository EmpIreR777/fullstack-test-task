# Fullstack Test Task — FileGuard

**FileGuard** — это fullstack-приложение для загрузки файлов, их антивирусной проверки и управления алертами безопасности. Проект состоит из **backend** (Python / FastAPI) и **frontend** (Next.js / React / TypeScript), объединённых через REST API и разворачиваемых через Docker Compose.

## Backend

### Функциональность backend

- **Загрузка файлов** — через REST API (multipart/form-data) с указанием названия; файл стримится на диск чанками и не читается целиком в ОЗУ.
- **Скачивание файлов** — по ID файла.
- **Обновление названия** — PATCH-запрос.
- **Удаление файлов** — DELETE-запрос.
- **Пагинированный список** — с поиском по названию и оригинальному имени.
- **Асинхронное сканирование** — через Celery задачи:
  - Проверка расширения на подозрительные (`.exe`, `.bat`, `.sh`, `.zip` и т.д.).
  - Проверка размера файла.
  - Проверка MIME-типа (особенно для PDF).
  - Извлечение метаданных (количество строк, символов, страниц) потоковым чтением, без загрузки файла в память.
- **Алерты безопасности** — автоматическое создание алертов (info / warning / critical) по результатам сканирования.
- **Логирование** — стандартный `logging` с уровнем из переменной окружения `LOG_LEVEL`.

### Запуск backend

#### Локально (без Docker)

```bash
cd backend

# Установка зависимостей
uv sync --all-groups

# Настройка .env (пример)
cp .env.example .env  # если есть

# Запуск сервера разработки
uv run uvicorn src.app:app --host 127.0.0.1 --port 8000 --reload
```

#### Через Makefile

```bash
cd backend
make run          # Запуск сервера
make sync-all     # Установка зависимостей
```

#### Через Docker Compose (из корня проекта)

```bash
make up           # docker compose -f docker-compose.dev.yml up -d --build
make down         # Остановка контейнеров
make logs         # Просмотр логов
make clean        # Остановка + удаление volumes
```

### Makefile backend

В `backend/Makefile` доступны следующие команды:

| Команда              | Описание                                          |
|----------------------|---------------------------------------------------|
| `make run`           | Запуск Uvicorn dev-сервера                        |
| `make sync-all`      | Установка всех зависимостей через uv              |
| `make alembic-rev m="..."` | Создание новой миграции Alembic            |
| `make alembic-up`    | Применение миграций                               |
| `make alembic-down`  | Откат последней миграции                          |

| `make mypy`          | Статическая типизация через mypy                  |
| `make clean-cache`   | Очистка кэшей (__pycache__, .mypy_cache и др.)    |

### Тестирование backend

Проект содержит **юнит- и интеграционные тесты** в директории `backend/tests/`.

**Запуск тестов:**

Локально:

```bash
cd backend
uv run pytest
```

Внутри Docker-контейнера (убедитесь, что контейнеры запущены через `make up`):

```bash
docker exec backend pytest tests/ -v
```

Флаг `-v` (verbose) покажет детальный результат по каждому тесту.

**Фикстуры тестов (conftest.py):**

- `event_loop` — создание event loop на сессию тестов.
- `async_session_maker` — фабрика сессий в рамках транзакции с откатом после теста.
- `db_session` — сессия БД для каждого теста.
- `client` — HTTP-клиент (httpx.AsyncClient) с подменой зависимостей FastAPI.
- `disable_logging` — отключение логов во время тестов (autouse).

**Файлы тестов:**

- `tests/test_files.py` — тесты для файлового API (загрузка, получение, обновление, удаление, скачивание).
- `tests/test_files_extra.py` — тесты файлового API.
- `tests/test_alerts.py` — тесты для API алертов (получение списка, пагинация, поиск).
- `tests/test_scan_task.py` — тесты для Celery-задачи сканирования файлов.

## Frontend

### UX/UI

Frontend представляет собой **современное одностраничное приложение** с тёмной темой, разработанное с акцентом на удобство использования и визуальную привлекательность.

**Ключевые особенности UX/UI:**

- **Тёмная тема** — все компоненты выполнены в тёмной цветовой гамме (slate/indigo), что снижает нагрузку на глаза.
- **Hero-секция** — приветственный заголовок с кратким описанием функционала.
- **Статистические карточки** — три карточки с иконками, описывающие основные возможности: загрузка файлов, антивирусное сканирование, алерты безопасности.
- **Таблицы с данными** — файлы и алерты отображаются в структурированных таблицах с сортировкой и пагинацией.
- **Поиск** — строка поиска с возможностью очистки и отображением количества результатов.
- **Модальные окна** — загрузка файла происходит через модальное окно.
- **Индикаторы загрузки** — Spinner при загрузке данных.
- **Обработка ошибок** — понятные сообщения об ошибках с визуальным выделением.
- **Адаптивность** — сетка 3 колонки для карточек, responsive-таблицы.

### Функциональность frontend

- Просмотр списка файлов с пагинацией.
- Поиск файлов по названию.
- Загрузка новых файлов (с указанием названия).
- Обновление названия файла.
- Удаление файла.
- Скачивание файла.
- Просмотр алертов безопасности с пагинацией.
- Поиск алертов по сообщению.
- Автоматическое обновление данных (refetch).

### Технологический стек frontend

| Компонент       | Технология                     |

| Фреймворк       | Next.js 14+ (App Router)       |

## Docker

Весь проект запускается через Docker Compose:

```bash
# Запуск всех сервисов (разработка)
make up

# Остановка
make down

# Просмотр логов
make logs

# Полная очистка (с удалением volumes)
make clean
```

**Сервисы в docker-compose.dev.yml:**

- `backend` — FastAPI приложение (порт 8000)
- `backend-worker` — Celery worker для фоновых задач
- `backend-db` — PostgreSQL база данных (порт 5432)
- `backend-redis` — Redis для Celery
- `frontend` — Next.js приложение (порт 3000)

> Примечание: перед первым запуском создайте `.env.dev` из шаблона: `cp .env.example .env.dev` (фронтенд обращается к бэкенду напрямую по `http://localhost:8000`, CORS уже настроен).

## CI / Линтеры

Проект использует **pre-commit хуки** для автоматической проверки качества кода:

- **Ruff** — линтер и форматтер Python.
- **mypy** — статическая типизация.
- **pre-commit** — запуск всех проверок перед коммитом.

Установка хуков:

```bash
cd backend
uv run pre-commit install
```

Ручной запуск:

```bash
cd backend
make lint
```
